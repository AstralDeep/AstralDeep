# Retained framework operations

On a server exposing the framework Work facade through MCP, a framework caller can read an existing operation or its retained result with the corresponding credential scope. Replaying a previously accepted submission returns its existing receipt. A new framework chat submission returns `turn_engine_retired` before consuming an admission.

With `FF_PERSISTENT_AGENTS` enabled, the node recovers expired reservations and closes unfinished active monitoring, research and chat assignments in bounded transactions on both SQLite and PostgreSQL. A live lease remains in force until expiry. An uncertain physical action stays available for reconciliation with its original accounting. Previously completed results retain their original verification requirements. Completion subscriptions use the recorded terminal outcome.

A personal mesh node exposes caller-ticket MCP and A2A doors. Its authentication boundary rejects framework bearer credentials, and the retired REST routes cannot submit or resume an assignment.
