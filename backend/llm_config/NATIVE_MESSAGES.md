# Native Messages candidate profile

This implements the **source-tested candidate subset** `anthropic-messages-text-tools/v1` for issue [331](https://github.com/AstralDeep/AstralDeep/issues/331). It is not configured-provider, staging, deployment, clinical, or cache qualification. `FF_ANTHROPIC_NATIVE` defaults off. Existing provider records, including `anthropic`, retain their OpenAI-compatible behavior. Enabling the flag only exposes a distinct `anthropic-native` selection through the existing server-owned provider catalog; it never reinterprets existing records.

The native selection must be saved through the existing encrypted owner or admin configuration path. The factory rejects plain or modified native configurations, mismatched credential scopes, unavailable capabilities, noncanonical endpoints, missing keys, or disabled profiles. Endpoint is exactly `https://api.anthropic.com/v1`; API header version is `2023-06-01`. Provider, explicit profile, owner, and an opaque digest of the entire encrypted record are retained in resolved/audit metadata. The private credential binding never appears in representations. The exact owner/scope record is checked before sending, before complete streamed text-block delivery, and before response/tool delivery, including after awaited audit work. Deletion, key rotation, model/provider/endpoint/revision change, or unavailable verification denies further use.

## Supported subset

- Leading system/developer instructions, user/assistant text, client-defined function tools, explicit strict tool settings, forced/automatic/none tool selection, and complete tool-result continuations through the ordinary orchestrator dispatcher. Structured argument JSON must be finite, bounded, object-shaped, and satisfy the supplied schema. Tools are returned as ordinary tool calls; the adapter never executes them.
- Complete JSON responses and fragmented SSE with ordered message/block events. Text emits at complete block boundaries. Tools emit only after the complete validated message and transport end. Cumulative counters overwrite earlier values. Errors, malformed input, incomplete JSON/streams, cancellation and revocation never trigger protocol downgrade or another physical native request.
- Normalized prompt/completion/total usage and cache read/write details. Native uncached input is exposed separately as `uncached_input_tokens`; generic `input_tokens` and `prompt_tokens` mean inclusive input. Missing cache counters keep inclusive input/total unknown even in existing context accounting. Inclusive output is counted once. Known consumption remains charged when a completed response is refused by validation or delivery authorization.
- Refusal retains the standard refusal/finish metadata. Truncated generation cannot become a completed response or dispatch tools; known usage remains available. A deliberately one-token saved-configuration connectivity check may accept a fully validated truncated text response solely as proof of connectivity, after record revalidation. It does not qualify a completed task.
- User/admin test actions preserve explicit provider selection. Native plaintext is encrypted through normal save first; it is not a prospective native transport credential. Native system saves retain the committed record if the subsequent native check fails and state that the save committed while the connection check failed. Existing compatibility save/probe behavior is unchanged. Native model discovery is explicitly unsupported; enter an exact model ID.

Thinking/signed or redacted continuations, hosted tools, cloud variants, images/files/audio, late system messages, structured-output requests, schema references, regex/format schema constraints, automatic cache markers, arbitrary endpoints/headers, ambient provider credentials and SDK tool runners are unsupported and rejected. Request and response model identities must match exactly; alias-to-canonical mappings are unqualified. Synthetic fixtures use `claude-sonnet-4-5-20250929`; this is not evidence that a model is available to any account.

The existing evidence/archive capture transport and fixed persistent research profiles have their own qualified provider contracts. Native cannot bypass them and is unavailable where those contracts require their existing compatibility profile. Ordinary governed native model calls retain persistent permits, input limits, output caps and cancellation; no harness/profile migration or component change is included.

## Bounds and transport

Native calls use `shared.external_http.async_post`, which reuses the pinned-address, verified TLS/SNI, header, write and close machinery in `shared.streaming_egress`. Every resolved address must be global/public, including embedded IPv4; no ambient private-host exemption applies. An explicit empty allowlist in the general helper now means no exemptions. No proxies, cookies, netrc, environment keys/custom headers, redirects, gzip, or unchecked DNS reconnection are used.

There is one physical request with no retry or compatibility fallback. Bounds are 60 seconds total, 1 MiB request, 2 MiB decoded response, 32 KiB/64 headers, 4096 HTTP chunks, 128-byte chunk-size lines, 64 KiB/event, 4096 SSE events, 64 content blocks/tools, 64 KiB tool arguments, JSON depth 32, 256 input messages, and 8192 output tokens. Lower persistent/caller output bounds are retained. Content-length and strict chunked framing are accepted; extensions, trailers, ambiguous framing, oversize and partial bodies fail closed. Cancellation or early consumer closure closes the pinned socket. No secrets or upstream response body enter transport exception messages.

Admission reuses `orchestrator.context_token_accounting` with a conservative 32768-token profile bound. Its unqualified encoding fallback is not a Claude tokenizer and does not establish native exactness or a cache minimum. No cache markers, prefix approvals, saved prompt store or warm-up calls are introduced. Cache policy remains the separate issue [333](https://github.com/AstralDeep/AstralDeep/issues/333) and repair branch.

## Contract evidence and remaining qualification

The hand-authored synthetic fixtures exercise actual encoded request bytes, fragmented SSE and the normal factory/invocation/audit/persistent boundaries with all unintended network paths denied. Contracts were checked against the official [streaming documentation](https://platform.claude.com/docs/en/build-with-claude/streaming) and immutable SDK type definitions at [`18f25547f20cf5f01da69ac611e700e3bc9ebf21`](https://github.com/anthropics/anthropic-sdk-python/tree/18f25547f20cf5f01da69ac611e700e3bc9ebf21/src/anthropic/types), accessed 2026-10-28. These establish a contract source, not vendor acceptance of this implementation.
