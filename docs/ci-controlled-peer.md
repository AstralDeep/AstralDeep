# Controlled CI peer utilities

`scripts/ci_network_fixture.py` provides a bounded synthetic TLS/DNS peer for an ephemeral Linux runner. The ordinary lint job qualifies its actual namespace/veth lifecycle. It installs no firewall, changes no production setting, and makes no claim that Fence is active or qualified.

Run `python scripts/ci_network_fixture.py qualify` on a disposable Ubuntu runner with its normal sudo available. Setup creates an invocation-specific namespace and veth pair on the connected documentation prefix `192.0.2.0/30`. It changes neither the default route nor host DNS or firewall rules. Existing conflicting routes or resource identities cause refusal. The peer has no default route and drops supplementary groups, uid/gid and capabilities after binding.

The fixture answers synthetic HTTPS requests on ports 18443, 19443, 443 and DNS on UDP 53. A new private test CA and nonce are generated for each invocation. The key stays mode 0600 in root-owned `/run/astral-ci-peer/`; system trust remains unchanged. Responses contain only the nonce and counters. The normal qualification requires authentic responses on every path, then runs the same network-denial assertions and requires an organic failure because an excluded peer actually answered without a firewall.

The root supervisor accepts no commands or control listener. It waits only for its child or a bounded lifetime, then reaps that owned child and removes resources by recorded interface index and namespace inode. TERM, HUP and INT enter cleanup. A fixed authenticated peer-close request terminates only that peer. Lost native command completion without a recorded kernel identity is uncertain: it fails closed and must never be reported as successful removal or trigger deletion of an unproven object. Root-owned atomic receipts distinguish closure, setup failure, uncertain cleanup and failed cleanup. A failed diagnostic remains a failed job; runner disposal is containment, not a successful cleanup claim.

`scripts/ci_fence_fixture_verifier.py` is an inert read-only adapter for the reviewed Fence v0.10.5 action commit `abc5790eac3445fe3854eea6b506aa7d31bed67c`. Its exact inputs are declared in [the tooling manifest](../tooling/ci-peer/inputs.json). It verifies all six protected runtime file digests, reuses the actual upstream report/readiness/DNS/unit validators through the runner's genuine Node 24, and tests a checksum-invalid private copy without modifying the live action. Missing or malformed evidence, a wrong runtime, stale health, unsuccessful peer baseline or unmatched rejections fail closed. Synthetic unit documents are parser tests and carry no acceptance authority.

The verifier requires an actual separately installed compatible Fence action and cannot prove enforcement in an unfenced job. This companion does not activate it. A later pilot must first consume only the exact reviewed default-branch helper bytes and hashes, prepare and baseline the fixture, install Fence before untrusted checkout/dependency execution, verify fresh controlled denials and real integrity evidence, and attest cleanup before executing candidate content. There is no runnable placeholder, policy exception, new secret, OIDC scope, privileged dispatch surface or approval claim here. The existing lint job remains within its 10-minute limit; other lane behavior is preserved.
