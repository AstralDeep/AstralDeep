# Accountless personal mesh roster v2

The active roster envelope is exactly `author, body, clock, follows, mesh, sig, type, v`, plus `presence_sig` where required. `v` is integer `2`. Signatures cover `astral.roster/v2\n` followed by canonical JSON excluding `sig` and `presence_sig`. Entry ids are the canonical hash of that same JSON without the context line. The mesh id is the first valid genesis entry id and is the owner-isolation principal. Version 1, mixed versions, unknown fields, `attest` and `issuer` entry types are rejected without admission. Preserved version 1 stores are unsupported and never reset or reassigned.

Genesis has exactly `device, epoch, recovery`; add has exactly `device`. Device certifications retain `astral.pairing/v1`, signed membership, feed and key binding. All other existing member removal, cutoff, epoch, wrap, stop, resume, rename, PHI-authority and PHI-approval bodies retain their existing validation. No token, issuer, subject, accepted-issuer list, identity attestation or unattested-member state establishes identity. Existing PHI destination authorization remains fail closed and is independent of membership. [phi-destinations.md](phi-destinations.md) defines who approves PHI destinations and holds PHI over these same entries.

`create_mesh() -> RecoveryKit` needs no network or issuer configuration. Presence approval signs the genesis. A single encrypted pending document durably stores the roster, recovery words and restore marker, bound to the current device and wrapping key. The runtime stays `Creating`, and `MeshStatus.recovery_pending` is true until `confirm_mesh_recovery() -> ()` succeeds. Duplicate calls and reopening return the same pending kit only after a fresh presence signature over `astral.recovery.export/v2\n<mesh-id>`. Confirmation requires a signature over `astral.recovery.confirm/v2\n<mesh-id>`, persists/activates the local feed and mesh content key, then removes the pending export before allowing ordinary runtime operations. Failed persistence or activation retains recoverable pending state.

The active durable metadata namespace is `mesh.v2.roster`, `mesh.v2.local`, `mesh.v2.pending_recovery`. Existing `mesh.roster` is detected as unsupported before any roster mutation. Host data-directory and key namespaces must likewise use v2 and preserve legacy data.

The host-facing principal contains only `mesh_id`; status replaces the identity-attestation fields with `recovery_pending`. Device records omit attestation state and timestamps, roster records omit issuers, and Kernel configuration omits issuers. A personal allowance maps every signed member to its explicit policy allowance with no identity-attestation reduction or invented verification flag. PHI, tool consent, action-bound tickets, stop/removal and replay checks remain enforced.

The deterministic vectors are generated with public test secrets by `reference/generate_local_vectors.py`. They reuse only the fixed cryptographic/test-key helpers from the preserved 105 reference; that reference's v1 roster evaluator is not an authority for v2.
