# Caller ticket `astral.caller/v1`

A caller ticket lets a script, an MCP client or another agent call one personal node with no sign-in. An owner device mints it with a presence signature. The caller holds a separate key and signs every request with it. The ticket is not a secret, because a leaked ticket does nothing without the holder key.

It is a sibling of `astral.ticket/v1`, which stays unchanged. That ticket needs a turn block and a per-call action digest that a script cannot produce. Existing roster v2 stores keep working unchanged. This contract adds no event type, no roster field and no new body field. Devices on the deployed kernel fold a caller revoke as an ordinary `auth.revoke`.

Reference code: `reference/caller_ticket.py` and `reference/ed25519_strict.py`. Generator: `reference/generate_caller_vectors.py`. Vectors: `vectors/caller-v1.json`. Label table: `reference/label_classes.json`, generated by `reference/generate_label_classes.py`. The signing helpers, LETS-CJ/1 and the tool definition hash come from the preserved 105 reference.

## 1. Ticket

A JSON object with exactly these fields. Any other field is `caller.malformed`.

| Field | Meaning |
|---|---|
| `v` | The integer 1 |
| `id` | base64url of 16 random bytes |
| `mesh` | The mesh id, `sha256:` and 64 lowercase hex characters |
| `device` | The minting member, a device id. Its roster kind must be `desktop`, `pocket` or `satellite` |
| `node` | The target member, a device id of kind `node` |
| `holder` | base64url of the caller's raw 32 byte Ed25519 public key. It must be the canonical encoding of a point on the curve that is not of small order and lies in the prime-order subgroup |
| `label` | 1 to 64 Unicode code points typed by the owner. A code point in a range of the committed table `reference/label_classes.json` is refused |
| `tools` | 1 to 32 entries sorted by `name` and without repeats, each with exactly `name` and `def` |
| `issued_ms` | Mint time in milliseconds |
| `expires_ms` | Expiry in milliseconds |
| `stop` | The mesh stop counter at mint |
| `sig` | The minting device's signature |

A tool entry names either a catalog tool or the reserved `a2a.message`. For a catalog tool `name` matches `[A-Za-z][A-Za-z0-9_-]{0,63}` and `def` is the `tools.md` definition hash taken from the node's current catalog. For `a2a.message`, `def` is `null` and the ticket lets the holder send A2A messages to the node.

### Holder key

A usable holder key `A` passes four checks. Its 32 bytes are a canonical encoding, so `y` is below `p` and `x` is not zero when the sign bit is set. It decodes to a point on the curve. `[8]A` is not the identity, so `A` is not of small order. `[L]A` is the identity, where `L` is the prime group order, so `A` is torsion-free. The identity point is torsion-free and of small order, which is why both of the last two checks apply. A mixed-order key, a prime-order point plus a small-order one, passes the small-order check and fails the torsion check. Library strict modes often skip the torsion check, so an implementation computes `[L]A` itself. A torsion-free key removes the disagreement between cofactored and cofactorless verifiers that a mixed-order key causes. The other source of that disagreement is a mixed-order `R`, and section 2 closes it.

No non-canonical encoding of a usable key exists. Every 32 byte string with `y` at or above `p`, with either sign bit, names a point that is off the curve, of small order or outside the prime-order subgroup. The only other non-canonical form, `x` zero with the sign bit set, names the identity or the order 2 point. The canonical rule is kept so that decoding matches RFC 8032.

### Label

A label is 1 to 64 Unicode code points. A code point whose Unicode 16.0 general category is Cc (control), Cf (format), Cs (surrogate), Co (private use) or Cn (unassigned) is refused with `caller.malformed`. Every implementation decides this from the committed table `reference/label_classes.json` and never from its runtime's Unicode data, so a different Unicode version in a runtime cannot change an outcome. The table holds, for each of the five categories, the inclusive first and last code points of its ranges. `reference/generate_label_classes.py` builds it from a Python whose `unicodedata` reports 16.0.0 and refuses to run on any other Unicode data. Its `--check` fails when the committed table differs. A surrogate cannot occur in canonical UTF-8, so Cs has no vector and the table lists it for completeness.

### Signature

`sig` is the minting device's presence key P-256 low-S signature over `astral.caller/v1\n` followed by the LETS-CJ/1 bytes of the object without `sig`. The signature is 64 bytes, `r` then `s`, as in the roster.

### Lifetime

The mint choices are 1 hour, 1 day, 7 days and 30 days. The default is 7 days. A ticket whose `expires_ms` is not after `issued_ms`, or is more than 30 days after it, is `caller.malformed`. A verifier refuses a ticket whose `issued_ms` is more than 5 minutes ahead of its own clock with `caller.not_yet_valid`.

## 2. Holder proof

Each request carries the header `Astral-Caller-Proof`. Its value is base64url of the LETS-CJ/1 bytes of an object with exactly these fields.

| Field | Meaning |
|---|---|
| `v` | The integer 1 |
| `ticket` | The ticket `id` |
| `method` | The HTTP method as sent, 1 to 16 characters |
| `target` | The path and query as sent, starting with `/`, at most 2048 characters |
| `body` | `sha256:` and the hash of the exact body bytes, the hash of the empty string for no body |
| `ms` | Proof time in milliseconds |
| `nonce` | base64url of 16 random bytes |
| `sig` | The holder's Ed25519 signature |

`sig` covers `astral.caller-proof/v1\n` followed by the LETS-CJ/1 bytes of the object without `sig`. Any other field is `caller.proof_malformed`.

The holder signature is verified strictly under RFC 8032. `S` must be below the group order, `R` must be a canonical encoding that is not of small order, and the recomputed `R` must equal the signature's `R` bytes. These are the `verify_strict` rules. A verifier whose library is more lenient adds the checks itself. A small-order holder key would otherwise let anyone forge a proof for any message, which is why step 1 refuses such a key, and step 1 refuses a mixed-order key for the reason given in section 1.

A small-order `R` is `caller.proof_bad_signature` even when `S` is honest for that `R`. Such an `S` is `k·a mod L`, where `a` is the clamped holder scalar and `k` is SHA-512 of `R`, `A` and the signed bytes, reduced mod `L`. A library with no small-order `R` check accepts the identity `R`, as OpenSSL, CryptoKit and the dalek `verify` call do, and libsodium refuses it. A cofactored check accepts the honest `S` for every small-order `R`. The vectors `proof_small_order_r_identity`, `proof_small_order_r_order_2`, `proof_small_order_r_order_4` and `proof_small_order_r_order_8` pin each case.

The check is the cofactorless equation `[S]B = R + [k]A`, compared as encoded bytes. A cofactored check, `[8][S]B = [8]R + [8][k]A`, is not enough. With a torsion-free `A` the two differ only on an `R` that is a prime-order point plus a small-order one. That `R` fails the cofactorless equation, so it is `caller.proof_bad_signature`, and the vector `proof_mixed_order_r_cofactored_only` pins a proof that only a cofactored check accepts.

A proof is in time when `now - 120000 <= ms <= now + 5000` and `ms > started_ms + 5000`, where `now` is the verifier's clock in milliseconds and `started_ms` is the start of the replay store, taken when the store is created and shared by every process that verifies for the node. Both failures are `caller.proof_stale`. The second bound means no proof that a verifier could have accepted before a restart is accepted after it. The cost is a 5 second pause after each restart. A proof dated exactly 5 seconds after the store started is refused.

The replay store is keyed by ticket id and nonce. An entry is held while `now <= ms + 120000`, in memory, and is shared by every process that verifies for the node. A verifier records the key only after the holder signature has verified, so a forged proof cannot use up a nonce. The key does not include the target, the proof time or the signature, so a fresh proof that reuses a ticket id and nonce is a replay. A clock that steps backward is a known limit. A verifier whose clock steps back may accept a proof the store already forgot, and a node should not run with a clock it cannot trust. A leaked ticket alone does nothing, so the ticket is not a secret.

## 3. Transport

The ticket travels as `Authorization: AstralCaller <base64url ticket>`. Only the `AstralCaller` scheme is read, and it is matched exactly. Any other scheme, including a different letter case, even with a valid ticket after it, is `caller.malformed`.

Ticket and proof bytes must be exact canonical LETS-CJ/1. A verifier decodes the base64url, parses strictly, re-encodes and compares the bytes. Spacing, key order or any other difference is `caller.malformed` for a ticket and `caller.proof_malformed` for a proof. Undecodable bytes, text that is not valid UTF-8 and any header over 8192 characters are refused before decoding, with the same codes and never with an exception.

Three text forms exist for copying and pasting.

- `astral-caller-ticket:v1:<base64url>` carries the ticket bytes. It is not a secret. Parsing it applies the ticket rules of section 1 and the canonical byte rule, and yields the ticket id and the `Authorization` header value.
- `astral-caller-holder:v1:<base64url>` carries the raw 32 byte Ed25519 public key of the holder. It is not a secret. Minting takes only this form and refuses a key that is not usable as defined in section 1, with `caller.malformed`. That covers a key that is not a canonical point encoding, is off the curve, is of small order or lies outside the prime-order subgroup.
- `astral-caller-key:v1:<base64url>` carries the 32 byte Ed25519 seed of the holder key. It is a secret. The caller keeps it and never pastes it into a minting device. An editor that mints a ticket accepts only the holder form and refuses the key form with a message that says so.

A text form with another prefix or version, padding, a non-canonical encoding, a ticket over the header limit or the wrong key length is `caller.malformed`. The prefix match is exact and case sensitive. The 8192 character limit of a ticket text form counts the whole text including its prefix. A text form that is canonical but fails the ticket rules, such as one with no tools, is refused. The key form derives the holder form, and the vectors pin that.

## 4. Verification

The verifier is given its own view of the mesh and does not read anything from the caller beyond the two headers and the request.

| Input | Meaning |
|---|---|
| `mesh` | The mesh the node is bound to |
| `node` | The node's own device id |
| `members` | Current members, each with its `presence` public key and `kind` |
| `removed` | Removed device ids |
| `stop` | The current stop counter |
| `revokes` | The authority revoke keys, each `agent/tool/scope` |
| `grants` | The authority grant keys in the same form. A caller ticket check never reads them |
| `catalog` | The node's current catalog, tool name to definition hash |
| `now_ms`, `started_ms` | The verifier's clock, and its clock reading at the start of the replay store |
| request | `method`, `target`, `body` and the `tool` the request names |

The first failure wins, in this order.

| Step | Check | Code |
|---|---|---|
| 1 | Ticket shape, exact canonical bytes, lifetime, header size, label code points, a usable holder key | `caller.malformed` |
| 2 | Proof shape, exact canonical bytes, header size, presence | `caller.proof_malformed` |
| 3 | `mesh` equals the verifier's mesh | `caller.mesh_mismatch` |
| 4 | `node` equals the verifier's node | `caller.wrong_node` |
| 5 | `device` is a current member and not removed. An unknown device is treated as removed | `caller.device_removed` |
| 6 | The member's roster kind is `desktop`, `pocket` or `satellite`. A member of kind `node` cannot mint | `caller.wrong_minter` |
| 7 | Presence signature verifies against that member's roster key, low-S only | `caller.bad_signature` |
| 8 | The current stop counter is not above the ticket's `stop` | `caller.stopped` |
| 9 | `expires_ms` is after the verifier's clock, so an expiry exactly at `now_ms` is expired | `caller.expired` |
| 10 | `issued_ms` is at most 5 minutes ahead | `caller.not_yet_valid` |
| 11 | The ticket `id` is not revoked | `caller.revoked` |
| 12 | The proof names this ticket, method, target and body hash | `caller.proof_mismatch` |
| 13 | The proof is in time as defined in section 2 | `caller.proof_stale` |
| 14 | The holder signature verifies against `holder` | `caller.proof_bad_signature` |
| 15 | The ticket id and nonce were not recorded before | `caller.replayed` |
| 16 | The request's tool is in the ticket | `caller.tool_not_covered` |
| 17 | A catalog tool's `def` equals the node's current definition | `caller.tool_changed` |

A ticket whose `stop` is above the node's stays acceptable until the node's stop reaches it, the same as the 105 ticket rule.

Steps 9 and 10 cannot both fail on a ticket with a valid lifetime, because an expired ticket was issued in the past. Steps 16 and 17 cannot both fail for one tool. The vectors pin every other adjacent pair, so the order of those two pairs is not observable.

A tool the ticket covers that the catalog no longer lists is `caller.tool_changed`. The tool `a2a.message` has no definition, so step 17 does not apply to it. A verifier records the nonce once step 15 passes, even if step 16 or 17 then refuses the request. A proof that fails step 14 does not use its nonce.

A request that names no tool (`tool` absent or null, the MCP `tools/list` call) runs steps 1 to 15 and skips 16 and 17. The result lists the ticket's covered tool names.

Two more codes sit outside the verifier because they depend on the endpoint. `caller.tool_unavailable` means the ticket covers a tool the endpoint cannot dispatch. `caller.no_catalog` means a mint was attempted against a node that has published no catalog.

Deep maps `caller.malformed`, `caller.proof_malformed`, `caller.bad_signature` and `caller.proof_bad_signature` to HTTP 401 and every other code to 403. A successful check returns the caller id, the label, the mesh and the covered tool, or the covered tool names when the request named none. The endpoint compares the mesh with its bound owner.

## 5. Revocation

Any member revokes a ticket by writing an `auth.revoke` event whose body has agent `caller:<id>`, tool `*` and scope `*`. Only that exact shape revokes a caller ticket. A revoke for `caller:<id>` with another tool or scope, or for another caller id, does nothing to the ticket, and the vectors pin each. A revoked ticket stays revoked. A later `auth.grant` that names `caller:<id>` never restores it, so a verifier must not apply the generic grant-over-revoke rule to callers.

The authority fold accepts any agent string, so the deployed kernel folds it as an ordinary revoke that matches no real agent. Beside it, the 105 grant check still passes for an ordinary agent action that has no grant. The vector `caller_revoke_fold` uses no grants, a caller revoke and an ordinary action, and expects the check to pass. Its control adds a revoke of `agent-a/*/*` and expects `ticket.grant_revoked`, which shows the check discriminates.

Removing the minting device or raising the stop also refuses its tickets. Deployed apps that list authority entries may show a `caller:<id>` revoke row.

## 6. Minting and node side

These parts belong to the kernel and are listed here so every implementation agrees.

- `mint_caller_ticket(node, holder_key, label, tool_names, a2a, lifetime_s)` runs on an owner device and takes only the public holder form of the key, never the seed. It resolves each `def` from the node's current catalog fold, so a host never supplies a hash. The kernel draws the presence prompt from the ticket fields and never from model output.
- The minting device keeps an index of its tickets under the meta key `mesh.v2.callers`. `caller_tickets()` lists them with `revoked` and `expired`. `revoke_caller_ticket(id)` is idempotent.
- `verify_caller_request(...)` does every check in section 4, including replay.
- The node's published mesh catalog is the source of truth for tool names and definitions. MCP `tools/list` verifies with no tool and returns the ticket's tools that the endpoint can dispatch.

## 7. Vectors

`vectors/caller-v1.json` uses the vector format of the roster v2 contract. State is given to the verifier directly and is built from the roster v2 test devices with public test keys. The devices are `alice` (kind `desktop`), `bob` (`pocket`), `carol` (`satellite`) and `node` (`node`). The file publishes the holder and stranger seeds and the presence scalars under `test_keys`, so a consumer can recompute every ticket and proof byte. All of them are public test values derived from the labels the generator names.

Case kinds:

- `caller_verify` has `state`, `authorization`, `proof` and `request`. The expectation is `{"ok": {"caller", "label", "mesh", "tool" or "tools"}}` or `{"error": code}`.
- `caller_verify_sequence` has `state` and `steps`, each with the fields of a single case. A step may carry `state`, a patch merged into the verifier state before it runs (it can move `now_ms`), or `restart`, which replaces the verifier with a new one that has an empty replay store. The new verifier's state is the case state with every earlier `state` patch and then the `restart` values applied. Patches persist across later steps. Within one step the `state` patch applies first and the `restart` values after it, so a `restart` value wins over the same key in `state`. The expectation is `{"ok": {"results": [...]}}` with one result per step.
- `caller_revoke_fold` has `caller`, `grants`, `revokes`, `action` and `effect_kind`. It expects the revoked caller ids and the pass of the ordinary grant check, or the `ticket.grant_revoked` error.
- `caller_ticket_text`, `caller_holder_text` and `caller_key_text` have `text`. They expect the parsed ticket id and header, the parsed holder key, or for the key form the derived holder key and holder text.
