# GaiaKeep agent contract

Agent id `gaiakeep-1`; registration requires `FF_GAIAKEEP=true` AND `FF_CRESCO=true`, both default off. Default `GAIAKEEP_CONNECTION_MODE=ssh` uses only the caller's encrypted registered-machine SSH credentials. The enrolled Gaia profile, P-384 key and gateway service key remain in that DGX account. Native compatibility retains encrypted agent credentials and the environment-only fabric key. Gaia is an untrusted source, every mutation is a taint sink, and startup does not grant the safe-agent permission baseline. Standalone binds loopback; in-process placement uses normal authenticated dispatch.

The factual catalog contains 111 declarations at gfs `02f7d83cc92db50968d4076da8afad2cc7a811b7`: 90 core and 21 prototype/common actions. There are 111 tools: 107 native control surfaces, two bounded file workflows and two read-only SSH account-discovery tools. `core.put`, `core.get`, `core.haveopen`, and `core.have` belong to those workflows because encryption/key exchange and stream lifecycles cannot be completed by a stateless RPC. Legacy `fetch` is an explicitly unsupported named surface until its receiver is implemented and qualified.

Controls use `gaiakeep_<action with dots replaced by underscores>`, `machine_id`, and a closed `params` object matching declared names/types/required fields. There is no arbitrary-action tool. Authentication, signature, stream, routing, and caller fields are protected. Only specific server-owned context fields are stripped; other extras are refused. The orchestrator overwrites `user_id` before approval fingerprinting and retains delegation, per-tool permission, PHI, policy and audit checks. Scope is read for proven reads, write for mutations, and system for privileged/legacy operations. Every non-read needs exact-argument, owner-bound, single-use approval; unattended mutation is refused.

`gaiakeep_upload_file(machine_id, collection_id, path, data_base64, branch=main, strategy=ingest, base_vid?, expected_head?, request_id?)` publishes one relative file, up to 8 MiB decoded, and moves the branch head. `base_vid` preserves other files; `expected_head` guards concurrency. Ingest accepts a 16–64 character ASCII alphanumeric/underscore/hyphen request ID for explicit reconciliation. `strategy=have` accepts neither `base_vid` nor `request_id`. Upload needs exact confirmation and uses only agent-owned temporary files. `gaiakeep_read_file(machine_id, vid, path)` returns up to 8 MiB authenticated bytes as base64, count and SHA256; bytes stay outside the preview.

SSH execution uses a fixed isolated Python bootstrap whose public source digest binds the first-party adapter bundle. Request bytes travel on stdin, never argv. SDK source/resources are pinned by the exact 0.2.0 artifact lock, privately snapshotted, and compiled from verified bytes; preloaded or drifting modules are refused. Profile/key reads are bounded, nonblocking and require owner-only regular files. The adapter ignores profile host/insecure transport flags, compares core/key/port/peers with operator trust, and routes only to login-node loopback. It reuses the verified native wire implementation below. The entire SSH operation is bounded to 120 seconds, stdin/file responses to 13 MiB, ordinary results to 1 MiB and discarded diagnostics to 16 KiB. Backend verifies returned file identity/count/digest again. Raw remote exception payloads never return.

Control uses verified `wss` over the pinned SSH machine to fixed remote `127.0.0.1:<operator gateway port>`, `/api/apisocket`, and the runtime `cresco_service_key` header. EXEC routes and SDK redirects admit only configured region:agent:plugin triples. `/api/dataplane` uses the same CA, hostname verification and service key, waits for activation, and carries SDK-owned encrypted GKT flows. There is no unverified TLS mode. Correlation is exact; RPC replies are bounded to 1 MiB and gzip expansion to 4 MiB per field and in aggregate. Permissive upstream base64 decoding cannot bypass preflight.

Signatures/nonces and RPC IDs are code-owned. A caller may supply a validated native `request_id` where declared; otherwise one is generated once. Controls and ordinary ingest retain that ID in success/error reconciliation data, and write errors display it. Have-upload reconciliation identifies collection, branch and path. These are reconciliation inputs, not completed-job claims. The wrapper does not replay uncertain mutations.

Results use approved Card/CodeBlock components and structured data. Verdicts: `ok`, `not_configured`, `unavailable`, `auth_failed`, `invalid_argument`, `upstream_denied`, `protocol_error`, `integrity_error`, `unsupported`, `unconfirmed`. Errors use the error envelope with verdict/reconciliation data, never a combined success result. Errors do not echo upstream exception payloads. Post-dispatch parsing failures/disconnects are unconfirmed; preflight argument failures do not imply an effect.

The tool handler automatically records failures as operational diagnostics in normal logs and, when configured, `GAIAKEEP_ISSUE_LOG_DIRECTORY/ISSUES.md`. Entries contain UTC time, a catalog tool name, closed verdict and dispatch/mutation state; no caller identity, request ID, credentials, arguments, data, paths or raw exception message is recorded. Rotation bounds the sink and preserves existing notes. A refused/unavailable sink emits a safe logging warning while the original tool result remains unchanged. Authorization refusals handled before the Gaia tool handler remain on the ordinary audit path. This log does not replace AstralPlane audit or storage state.

`core.extractproof` verifies exact certificate bytes/signature and extract ID against the pinned core key. `verified_certificate` retains exact public bytes only if redaction leaves them intact; otherwise it omits the artifact and marks verification false. `leaf_inclusion_verified` is false: this wrapper does not claim a full Merkle inclusion check. Caller-authentication signatures and credentials stay filtered.

Legacy controls require `GAIAKEEP_ALLOW_LEGACY=true` and system permission. Signed prototype user/approver identity derives from encrypted credentials and uses the core's peer audience. Restore destinations stay beneath a non-root operator-controlled absolute directory. Legacy `fetch` refuses before connection because its bounded receiver is incomplete. Legal-order `action=shorten` refuses before dispatch because of the upstream routing/signature collision; erase remains available. Linux transfers, live endpoint and real clients remain unqualified.

SSH account discovery uses gaiakeep_connection_info for the enrolled principal/tenant/default collection and gaiakeep_list_collections for SDK-known collections and heads. Neither accepts profile paths or credentials. These are distinct from mutating core.profile policy operations; native compatibility refuses the local discovery tools.
