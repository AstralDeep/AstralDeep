# Contract: Mac update feed and release pipeline

## Versions

- `MARKETING_VERSION` 1.9, `CURRENT_PROJECT_VERSION` 70 for the first updater-enabled build. Build numbers strictly increase across every later release. The first self-delivered update is 71.
- `tests/release/test_client_identity_continuity.py` is updated to the new numbers; the DirectDownload identity assertions are kept and extended with the Sparkle keys.

## App configuration (Projection, `apple-clients`)

- SPM dependency `https://github.com/sparkle-project/Sparkle` exact `2.10.1`, product `Sparkle`, Embed and Sign on the AstralApp target for macOS only.
- Info.plist (macOS): `SUFeedURL = https://astraldeep.github.io/appcast.xml`, `SUPublicEDKey = <base64>`, `SUEnableAutomaticChecks = true`, `SUScheduledCheckInterval = 86400`, `SUAutomaticallyUpdate = false`, `SUVerifyUpdateBeforeExtraction = true`, `SUShowReleaseNotes = true`. `SURequireSignedFeed` is set to true once the release command signs the feed (second release onward).
- Entitlements unchanged (audio input only). No library-validation exception.
- `UpdateCoordinator` (new, macOS only): owns `SPUStandardUpdaterController`, implements `allowedChannels(for:)` (preview opt-in), `shouldPostponeRelaunchForUpdate` (postpone while a computer, browser or command task is active), `updaterDidNotFindUpdate`, `didAbortWithError`, `didFinishUpdateCycleFor`, and `supportsGentleScheduledUpdateReminders`. Publishes `canCheckForUpdates`, `lastCheck`, `pendingRelaunch`, `lastError` for the UI.
- Menu: `CommandGroup(after: .appInfo)` with `Check for Updates…`.
- Settings: Updates section with automatic checks, automatic install, preview channel, current build, last check, and a Check now button.
- Status indicator: a small chip in the workbench toolbar area when an update is downloaded and waiting, or when the last scheduled check failed.

## Minimum-version policy

`https://astraldeep.github.io/data/mac-update-policy.json`

```json
{"schemaVersion": 1, "minimumBuild": 70, "serial": 3, "expires": "2027-01-01T00:00:00Z", "message": "Update required"}
```

A sibling `mac-update-policy.json.sig` holds the Ed25519 signature of the exact JSON bytes, produced by `sign_update -p`'s key (the same EdDSA key as the appcast). The app verifies with CryptoKit against the raw bytes of `SUPublicEDKey`. Rules: refuse to connect and show the update-required state when `CFBundleVersion < minimumBuild` and the signature verifies and `expires` is in the future and `serial` is not lower than the last seen serial. Any fetch, parse, signature or expiry failure means the policy is absent: connect normally and surface the failure in the status indicator. The app caches the last verified policy for 24 hours.

## Appcast

`https://astraldeep.github.io/appcast.xml`, generated by `generate_appcast`, enclosures pointing at `https://github.com/AstralDeep/AstralDeep/releases/download/macos-v<ver>-<build>/AstralDeep-<ver>-<build>-arm64.zip`. Default channel for stable releases; `<sparkle:channel>preview</sparkle:channel>` for previews. Inline markdown release notes from `<zipname>.md`. `--maximum-deltas 0` for the first releases. The live appcast is copied into the staging folder before generation so older items are preserved; only the newest archive is staged.

## Downloads record

`data/downloads.json` keeps its closed schema. The website gains `tests/appcast.test.mjs` and a build-time check in `scripts/build.mjs` that the newest appcast item's enclosure URL, length and version match `downloads.json`, and that the appcast parses. The appcast and policy files live under `site/` and are copied verbatim.

## Release command (Deep, `scripts/release_macos.py`)

Runs on the owner's Mac. Inputs: Projection commit, version, build, channel, release notes path, EdDSA key account, `--publish` flag. Steps:

1. Verify clean trees and that Deep's pin equals the Projection commit.
2. `xcodebuild archive` with the DirectDownload scheme, `ASTRAL_DEVELOPMENT_TEAM=593LGH35GS`, Developer ID identity; export the app.
3. `codesign --verify --deep --strict`, entitlement equality, Team ID, hardened runtime, version and build checks (reuse `package_macos_candidate.inspect_app`).
4. `ditto -c -k --sequesterRsrc --keepParent` to the archive name; `xcrun notarytool submit --keychain-profile astral-notary --wait`; `xcrun stapler staple` on the app, re-zip, `spctl --assess`.
5. `sign_update` and `generate_appcast` into a staging folder seeded with the live appcast; write `SHA256SUMS`; write `release-provenance.json` in the existing schema; write the new `downloads.json` record; sign `mac-update-policy.json` if its inputs changed.
6. Without `--publish`: stop and print the staging folder. With `--publish`: create the immutable GitHub prerelease or release with the tag, upload the archive, `SHA256SUMS` and provenance, wait until the asset URL answers 200, then create a branch in the website checkout with the appcast, downloads record and policy, run `npm test`, `npm run check` and `npm run build`, and open the pull request. Publication is never implicit; the owner says when.

## Install and relaunch

Sparkle performs the swap. The app shows "Update ready, restart when idle" while postponing. On quit, a staged update installs. Build 70 is installed by hand once; every later build arrives through the feed.
